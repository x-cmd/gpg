# Core Content

core_features:

- File layout: `keyring/<handle>.asc` per key + `keyring/keyring.asc` aggregate + `index.tsv` manifest
- New key flow: gpg --gen-key → gpg --armor --export → self-sign with detach-sig → append row to index.tsv → internal PR → second-pair review → release
- Aggregate regenerated by lexicographic handle concatenation; CI fails if regenerated != committed
- Four CI checks per push: gpg --list-packets parse, fingerprint-vs-manifest consistency, self-signature validity, fingerprint uniqueness across files
- Scenario: signing RPMs:
  - Import private key from CI secret (gpg --import --batch)
  - Set %_gpg_name + %_gpgbin in ~/.rpmmacros for unambiguous key selection
  - rpmsign --addsign (appends) vs --resign (replaces all)
  - Batch loop over /build/RPMS/*/*.rpm (multi-arch in one loop)
  - rpm -K basic / rpm -Kv verbose with fingerprint + UID
  - gpg-agent --daemon --max-cache-ttl + gpg-preset-passphrase for CI passphrase handling
  - Or rpmsign --passphrase-file (chmod 600 in CI secret store)
- Common pitfalls: public key not found (rpm --import), wrong key selected (set %_gpg_name), multi-signature semantics, passphrase prompt in CI, "package is not signed" on resign

## Key Information

highlights:

- The team is the only path to a commit on keyring/ or index.tsv — external PRs closed without merge
- keyring/keyring.asc is byte-stable across regenerations (lex handle order + blank line between keys)
- CI does NOT verify web-of-trust or trust signatures — consumer's responsibility via gpg --check-sigs
- rpmsign --addsign vs --resign: --addsign is day-to-day default (safer); --resign only when intentionally invalidating prior signatures
- Repackage / resign for LTS: rpmsign --addsign against existing release asset without recompiling
- Each release-CI step is independently auditable: which key signed (step 5 + cross-check vs index.tsv), what it signed (file list), when (release tag)

## Use Cases

use_cases:

- Adding a new maintainer's key to the keyring
- Rotating a key at expiry or after a compromise
- Diagnosing a CI failure on a keyring/ PR
- Setting up a release pipeline that signs RPMs with the team key
- Forensically confirming a release's key bytes match the team's intent

## Summary

The publisher's perspective on GPG keyring publication and RPM signing. File layout: `keyring/<handle>.asc` per published key + `keyring/keyring.asc` aggregate (concatenated in lex handle order) + `index.tsv` 5-column manifest. New-key flow: `gpg --gen-key` → `gpg --armor --export <KEYID>` → self-sign with `gpg --detach-sign --armor` → append row to `index.tsv` → internal PR → second-pair review → release; the team is the only path to a commit on keyring/ or index.tsv, external PRs closed without merge. CI gates every push with four checks: `gpg --list-packets` parse, fingerprint-vs-manifest consistency, self-signature validity on each key's primary UID, fingerprint uniqueness across files (no duplicates); CI does NOT verify web-of-trust or trust signatures — that's the consumer's job via `gpg --check-sigs`. Aggregate regenerated by lexicographic handle concatenation; CI fails if regenerated != committed. RPM signing scenario: import private key from CI secret (`gpg --import --batch`), set `%_gpg_name` + `%_gpgbin` in `~/.rpmmacros` for unambiguous key selection, batch-sign with `rpmsign --addsign` (appends signatures, day-to-day default) vs `--resign` (replaces all, only when intentionally invalidating prior signatures). Batch over `/build/RPMS/*/*.rpm` covers multi-arch in one loop. Verify with `rpm -K` (basic OK/NOK) or `rpm -Kv` (verbose, shows signing key fingerprint + UID — cross-check against `index.tsv` column 3). Passphrase in CI: either `gpg-agent --daemon --max-cache-ttl 3600` + `gpg-preset-passphrase`, or `rpmsign --passphrase-file <chmod-600-secret>` (rpmsign does not read `~/.bashrc` or pass `GPG_TTY` to gpg-agent). Common pitfalls: public key not found (fix `rpm --import`), wrong key selected (fix explicit `%_gpg_name`), multi-signature semantics (intentional for LTS repackage, use `--resign` to clean), passphrase prompt in CI (agent or `--passphrase-file`), "package is not signed" on resign (rebuild with `%_gpg_name` set during `rpmbuild`). Each release-CI step is independently auditable: which key signed (step 5 + cross-check vs `index.tsv`), what it signed (file list), when (release tag).
